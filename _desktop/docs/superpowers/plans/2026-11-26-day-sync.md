# Day Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phone and desktop build the identical day: the phone-only day inputs sync through the cloud key by key, the desktop runs the phone's current day logic on them, and goals are gone from desktop sync.

**Architecture:** One new cloud table, `day_inputs`, holds one row per input key (window, meals, each travel entry, each day's memory/events/ended/reschedules). Rows merge per key (last server write wins per key, unsent local edits win until acknowledged), so two devices editing different inputs never clobber each other. The phone mirrors AsyncStorage ↔ rows; the desktop mirrors rows into its local cloud SQLite and feeds them to a fresh copy of the phone's pure day modules.

**Tech Stack:** Supabase (Postgres, RLS, Realtime), Expo/React Native + Jest (phone, `/Users/erwan/Coding/Habyss`), Tauri 2 + Rust + rusqlite (desktop `apps/desktop/src-tauri`), React + TypeScript + Vitest (desktop `apps/desktop/src`).

**Spec:** `docs/superpowers/specs/2026-11-26-menu-bar-design.md` (decisions 6 and 7, Builder's calls "Goals", "Other days").

## Global Constraints

- Two repos: phone `/Users/erwan/Coding/Habyss`, desktop `/Users/erwan/Coding/Habyss Desktop`. Commit in each repo separately; never commit secrets.
- Migration name pattern `YYYYMMDD000N00_name.sql` under `supabase/migrations/`; follow `20261120000100_brain_dump.sql` conventions (owner RLS policy, `set_updated_at` trigger, `stamp_server_time`, `(user_id, updated_at)` index, `revoke all from anon`).
- Sync quality bar (spec decision 6): local-first, offline-safe, other device updated within seconds while both are online, per-input merge, nothing lost or duplicated.
- Desktop shared files are copies of phone files with a header `// Copied from Habyss Mobile lib/<file> @<phone commit>. Keep in sync; do not re-derive rules.` — copy, never re-derive.
- The day is computed in local time (phone `minuteOn` uses local `Date`).
- Phone tests: `npx jest lib/__tests__/<file> --watch=false`. Desktop: `cd apps/desktop && npx vitest run <path>` and `cd apps/desktop/src-tauri && cargo test`.

## Review Focus

1. **Both devices offline, then both edit different inputs** (phone changes meals, desktop's memory updates) → after reconnecting both edits survive. Test in Task 3 and Task 5.
2. **Same key edited on both devices** → the later server write wins on both, and neither device keeps its stale copy after the next pull. Test in Task 3.
3. **First launch after update on a phone that already has AsyncStorage values** → existing values upload once; a fresh desktop never overwrites them with defaults. Test in Task 3.
4. **Day rollover** (`ended:`/`reschedule:`/`day_memory:`/`events:` keyed by yesterday) → today's timeline ignores yesterday's rows; old dated rows are deleted after 14 days. Test in Task 2.
5. **Cloud still has goal rows / desktop has old goal columns locally** → desktop sync neither crashes nor re-uploads goal fields. Test in Task 6.

- Behaviour: dirty keys persist in AsyncStorage `day_inputs_dirty_<uid>` (survive restarts). Push = upsert dirty keys (`onConflict: 'user_id,key'`), clear a dirty key only if its value is unchanged since send (as `markUploaded`). Pull = rows with `updated_at >= cursor` (`day_inputs_cursor_<uid>`); a pulled key that is dirty locally is skipped; others are written to AsyncStorage through `storesFromRows` and each module's in-memory state is reloaded (`loadMeals`, `loadTravel`, `loadMemory`, …) so subscribers re-render. First run per user (no cursor): pull first, then mark dirty only the stores whose key has no server row (never overwrite server data with local defaults). After push, call `announceChange()` (`lib/livePulse.ts`). Delete `staleKeys` (set `deleted_at`).
